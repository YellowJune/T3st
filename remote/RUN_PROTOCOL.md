# Audited DFC v2 remote runs

The accepted remote evidence must satisfy the PyTorch bitwise trajectory/payload/checkpoint gate before any vision cell runs. CIFAR-100 is downloaded from the immutable mirror and verified against SHA-256 `85cd44d02ba6437773c5bbd22e183051d648de2e7d6b014e1ef29b855ba677a7`.

Run `31289144091` validated the original 32x32/4-bit reference codec and all nine execution paths. Its CIFAR accuracy rows were rejected after DFC-Sign+ER failed the empirical dominance gate; they remain preserved as negative evidence and are not used in the paper's performance claims.

Run `31290099638` tested normalized 16x16/4-bit ER at 300 updates per task. It restored current-task learning but failed the retention gate, so its vision rows are rejected.

The next pilot replaces batch-statistic state with GroupNorm and uses 16x16/4-bit exemplars plus 100 FP16 dark logits. Logits are captured from the already-counted current forward pass, so external DER++ and DFC-Sign+DER++ have identical dense neural FLOPs and auxiliary distillation work. The fixed batch contains 32 current and 32 replay examples; four current records enter the reservoir per step. The width-48 pilot is admitted to a final three-seed run only if it passes exactness, resource equality, and DFC-versus-external-DER++ retention gates.

Run `31290756632` passed optimizer/checkpoint exactness, dataset integrity, and every paired resource identity. Its DFC-Sign row reduced forgetting by 0.056 points and stayed within the one-point current-task margin, but final average accuracy was 7.40% versus 7.48% for external DER++. Because the predeclared Pareto rule requires nonnegative final-accuracy gain, the vision rows from this run are rejected and excluded from the manuscript.

The final matrix switches to the separately declared DFC-Low16 decoder, whose two FP32 Adam state tensors expose four logical bytes per parameter under BF16-high semantics. Before vision starts, the exactness job must pass a coupled canonical-reference trajectory, arbitrary unaligned payload writes, and checkpoint recovery for this decoder. The final methods are sequential, external DER++, and DFC-Low16+DER++; the fresh sealed seeds are `401`, `409`, and `419`. All nine cells use width 48, 300 updates per task, batch 64 with 32 replay positions, 32 KiB external allocation, four insertions per update, and distillation weight 0.3. Acceptance requires DFC-Low16 mean final accuracy no lower than external DER++, mean forgetting no higher, and current-task accuracy no more than one point lower, after every matrix hash, capacity law, and resource identity passes.

Run `31292229924` passed all exactness, dataset, matrix-hash, capacity, and paired-resource gates. DFC-Low16 improved mean final accuracy by 0.733 points and current-task accuracy by 3.467 points, but its mean peak-to-final forgetting was 0.293 points higher than external DER++. The predeclared rule therefore rejects all nine vision rows from the accepted aggregate.

The next sealed matrix changes the replay learning rule before drawing any new seed. Each replay method now places 48 replay records and 16 current records in the same batch of 64 and raises the already-counted dark-logit coefficient from 0.3 to 1.0. This directly targets old-task retention without adding a forward, backward, update, processed example, external byte, or dense neural FLOP. Both external DER++ and DFC-Low16+DER++ receive the identical replay count, coefficient, insertions, update count, and auxiliary distillation work. Fresh untouched seeds are `431`, `433`, and `439`. The acceptance rule is unchanged: DFC-Low16 mean final accuracy must be no lower, mean forgetting no higher, and mean current-task accuracy no more than one point lower than external DER++, after all exactness and resource gates pass.
